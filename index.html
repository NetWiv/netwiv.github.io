Why NetWiv

  1. Your backend stays .NET.

    NuGet packages, dependency injection, configuration and logging work the way they do in an ASP.NET Core app.

    var builder = NetWivApplication.CreateBuilder(args);builder.Services.AddSingleton<GreetingCounter>();builder.Services.Configure<GreetingOptions>(...);

  2. Types follow your C#.

    Records become TypeScript interfaces at build time, and a Blazor frontend gets a typed C# client, so the compiler catches a renamed field.

    public sealed record Greeting(    string Message,    int Count);
    export interface GreetingOutput {  "message": string;  "count": number;

  3. No browser engine inside.

    Pages render in the OS WebView. Your package carries your app, not a copy of Chromium.

  4. Choose how it ships.

    NativeAOT compiles your app into a native executable of a few files. Self-contained .NET is the default; an installed runtime is the other option. One flag.

Set up your coding agent

Give Claude Code, Codex or Cursor the guides for your NetWiv version and your project’s commands, through the CLI’s read-only MCP server.

Set up a coding agent

netwiv mcp runs a read-only MCP server from your project’s CLI. Your agent reads the guides for that NetWiv version and the project’s configuration, permissions and commands.

Let your agent do it

Paste this prompt into your coding agent. It installs what is missing, connects the server, offers the NetWiv skills in Claude Code and checks the connection.

Set it up yourself

Choose your coding agent.

  1. Add the NetWiv marketplace

    /plugin marketplace add NetWiv/skills

  2. Install the skills

    /plugin install netwiv@netwiv

  3. Reload plugins

    /reload-plugins

The skills work with every NetWiv version; version-specific guides come from your project’s CLI. Projects made with netwiv new already include .mcp.json: run dotnet tool restore once, and approve the netwiv server when Claude Code first loads it.

  1. Restore the project’s CLI

    dotnet tool restore

  2. Register the server in ~/.codex/config.toml

    [mcp_servers.netwiv]
command = "dotnet"
args = ["tool", "run", "netwiv", "--", "mcp"]

Start Codex from the project folder so dotnet tool run finds the project’s CLI.

  1. Restore the project’s CLI

    dotnet tool restore

  2. Add .cursor/mcp.json to the project

    {
  "mcpServers": {
    "netwiv": {
      "command": "dotnet",
      "args": ["tool", "run", "netwiv", "--", "mcp"]
    }
  }
}

The same registration as the project’s .mcp.json.

  1. Restore the project’s CLI

    dotnet tool restore

  2. Register a stdio server

    command:   dotnet
args:      tool run netwiv -- mcp
transport: stdio

Start it from the project folder. Before a project exists, a globally installed CLI serves the guides with netwiv mcp.
